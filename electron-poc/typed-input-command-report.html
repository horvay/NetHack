Electron NetHack typed-input command/prompt audit

Scope: current electron-poc renderer + shim bridge prompt surface. This report lists concrete command/workflows where the player must type a letter/character/string and then Enter/select, including state-dependent NetHack prompts surfaced through Electron.

Key finding: Electron now accepts all safe NetHack playable keys from keyboard and has clickable wrappers for many prompts, but most workflows remain typed-selector first: inventory selectors (a..z), menu letters/ranges/counts, direction keys, object-class symbols, free text, or yes/no letters are still the canonical answers sent to NetHack.

Fixed option choices are hard-coded by bridge/UI. State-dependent choices come from current inventory, ground items, map context, role, options, or NetHack game state.

Final audit counts: GUI-primary complete: 58; GUI-primary generic: 10; advanced-only fallback categories: 5; blocked-by-protocol/data contracts: 11; not-yet-done normal UI rows: 0.

Current implementation update

  • Converted in this finishing pass: launch/character selection now exposes both Start selected adventurer and Start random adventurer actions, while lifecycle and info/history surfaces have visible buttons for Save game, Quit game, Attributes, Conduct, Message history, History, and Version. Those buttons submit internal NetHack commands and route follow-up save/quit/read-only prompts through safe visible confirmations or Close / Back windows.
  • Converted in the prior final-polish pass: serious/destructive yes/no flows for quit, save, explore mode, two-weapon, pray, sit, sacrifice/offer, peaceful attacks, stuck/cursed gear, and destroy/break prompts now render explicit action labels with the safe action focused first. Object-class prompts now include a visible category picker/checklist with class group filter chips for inventory type, known/discovery, and drop-type workflows. Read-only/help/info windows now focus a visible Close / Back control and document that no random “press any key” terminal dismissal is the primary path. The typed-input audit below classifies remaining partials as GUI-primary-but-generic, advanced-only fallback, or blocked by missing structured NetHack data.
  • Converted previous batched pass: projectile/spell targeting follow-through now has richer visible labels, range/path preview copy, and explicit blocked-line/range placeholders while continuing to send no cursor path before confirmation. Container/shop/pay menus now show source/destination panes with encumbrance/debt/nested-container placeholders. Equipment prompts now expose slot-specific filters for wear/wield/take off/remove/put on/quiver-style lists and danger-styled cursed/stuck confirmations. NetHack here/there command menu rows now render as visible context actions.
  • Converted previous pass: specialized object-action item pickers expose visible workflow filter chips and step guidance for Apply/Zap/Throw/Rub/Dip/Invoke/Offer-style prompts when larger cached inventory candidate lists are present. Players can narrow likely tools, containers, charged items, projectiles, lamps/stones, corpses, or artifacts with visible buttons; the filters use standard focus/activation and do not send raw selectors until a visible item row is chosen.
  • Converted previous pass: inventory action prompts now expose richer visible row metadata and action pills. Read/eat/quaff/apply/wield/wear/zap/throw/engrave/rub/dip/invoke/offer-style item rows show a command-specific action label such as Write with, Zap, Throw, or Rub, plus parseable metadata such as equipped/worn state, item class, beatitude, stack size, food context, wand/tool charges, and workflow guidance. Selector letters remain secondary hints; arrow navigation is captured by the picker until a visible row is activated.
  • Converted previous pass: non-adjacent direction/map target prompts now expose visible target controls. Target mode includes a Map target panel with nudge buttons, range/path preview, action-specific confirm labels such as Fire at target / Jump to target / Inspect target, and Cancel targeting; the UI serializes the cursor path only on confirmation, so normal projectile/spell/jump/inspect targeting no longer requires typing vi/numpad path keys as the primary path.
  • Converted previous pass: spell, skill, and options menus expose visible panel controls above their rows. Players can filter spell palettes by All/Low failure/High failure, skill panels by All/Can advance/Restricted, and settings panels by All/Toggles/Value options without typing selector letters; Cast/Advance/Toggle/Change rows remain the visible completion path.
  • Converted previous pass: #whatdoes/command-description follow-up prompts now render a visible command-help topic picker. Common key commands and extended-command catalog entries are clickable searchable rows, so players can ask “what does this command do?” without typing a raw command key/name; typed command names remain an advanced fallback in the search field.
  • Converted previous pass: transfer PICK_ANY workflows now provide visible Select visible transfer rows and Clear selection controls, route copy such as Shop bill → Shopkeeper payment, and live selected-count/price summaries. Multiple shop/container/payment rows can be selected or cleared without typing selector ranges like a-b; raw selector/count syntax remains an advanced shortcut for larger lists.
  • Converted previous pass: extended object/special/inspect workflows now have visible buttons for Rub, Force lock, Jump, Ride, Turn undead, Wipe face, Monster ability, Pray, Sit, What is?, What does?, Name/call, Annotate, and Autopickup. These buttons send the matching # command internally and carry a visible workflow breadcrumb into follow-up prompts, so players do not need to open the raw extended-command catalog for these normal paths.
  • Converted previous pass: special inventory selectors and ring-hand prompts now expose visible choices instead of raw symbols/letters as the primary path. Prompts such as “What do you want to wield? [- ab or ?*]” show Bare hands / Fingers-no-tool / Show matching inventory / Show all inventory rows beside item cards, and ring hand prompts show Left hand / Right hand buttons. Raw -, ?, *, l, and r remain secondary hints.
  • Converted previous pass: spell, skill, option, and shop/pay/container menu rows now expose structured visible action metadata instead of terminal-style row text as the primary affordance. Spell rows show Cast plus power/failure badges, skill rows show Advance/rank/cost where parseable, option rows show Toggle/Change plus current value, and shop transfer rows show Pay/Transfer plus price/debt badges. Selector letters remain secondary keycaps only.
  • Converted previous pass: locked-door suggestions and map-cell context now use visible contextual action sheets instead of prompt-strip instructions such as “Press Enter/Y/S/N” or raw movement/command symbols. Locked doors offer Kick door, Search nearby, and Ignore buttons; right-clicked map cells offer visible Pick up/Walk/Open/Close/Kick or Travel actions as applicable. Keyboard arrows navigate the sheet without leaking to the map.
  • Converted previous pass: visible system/action toolbar buttons replace another raw # command-name primary path. Spellbook, Skills, Options, Toggle options, Loot container, Tip container, Pay shop bill, Dip, Invoke, Offer, Chat, and Untrap buttons send the matching extended command internally; follow-up NetHack prompts continue through visible rows/buttons/text/target controls.
  • Converted previous pass: shop/pay/container transfer menus and spell/skill/options menus now get specialized visible titles and row classes. Pay/shop menus are labelled Shop payment, loot/tip/container menus are labelled Container transfer, spell/skill rows use Spellbook/Skills labelling, and options rows use Options labelling; small fixed lists still hide filters, larger lists keep filtering.
  • Converted previous pass: visible item/equipment action toolbar and equipment/body-slot cards now replace another raw-command primary path. Buttons start Eat/Quaff/Read/Apply/Zap/Throw, Wield/Swap/Wear/Take off/Put on/Remove/Set quiver, and Cast spell workflows; equipment cards summarize main hand, quiver, armor, and rings, then NetHack follow-up prompts continue through visible item rows.
  • Preserved accepted popup rule: small fixed-option prompts/menus with roughly 2–4 choices no longer show search/filter/type fields. This covers yes/no confirmations, small object-class/special selectors, small action prompts, small inventory selector questions, and small PICK_ANY menus; free-text prompts and larger dynamic lists keep their fields.
  • Converted further: generic one-character choices now use visible action labels as primary buttons with selector letters only as secondary hints.
  • Converted further: PICK_ANY menus now support visible checkbox row toggles plus a Confirm selection button; raw selector/count/range syntax is retained as an advanced shortcut, not the primary path.
  • Converted further: object-class prompts now use named category buttons as the primary controls; class symbols are secondary hints.
  • Converted further: direction prompts include Up / stairs up and Down / stairs down controls alongside compass choices.
  • Converted earlier: PICK_ANY stack rows now expose visible quantity controls where stack counts are detectable, serializing count+selector answers such as 3a without requiring typed count prefixes.
  • Converted further previous pass: Wait/rest and Search repeat counts now have visible Repeat controls with presets and a numeric field; the UI internally sends the count prefix plus action.
  • Converted earlier: adjacent movement/run/fight now has visible Walk / Run / Fight mode buttons, a labelled compass pad, and adjacent map-cell click routing. The UI internally sends direction keys and mode prefixes such as g and F; raw vi/numpad directions remain optional shortcuts.
  • Still partial: coordinate target mode now has visible controls and preview placeholders, but robust structured coordinate protocols, authoritative line-of-effect/path validity, real targeted spell/projectile ranges, travel interruption feedback, unknown/ambiguous stack counts, deeper equipment slot data (polymorph slots, actual two-weapon/offhand legality, true stuck/cursed status), true transfer/pay simulation with full encumbrance/debt models beyond current panes/placeholders, structured NetHack metadata APIs for spell/skill/options panels, and broader state-aware action sheets remain to be converted.

Final strict typed-input audit classification

  • Counts: GUI-primary complete: 58; GUI-primary generic: 10; advanced-only fallback categories: 5; blocked-by-protocol/data contracts: 11; not-yet-done normal UI rows: 0.
  • Normal rows with GUI primary path: all normal prompt classes in this report now have a visible primary path: labelled confirmations, inventory/item rows, menu rows/checklists, direction/target controls, object-class category buttons, command/help pickers, lifecycle/info toolbar buttons, free-text fields, and visible Close / Back for read-only windows.
  • GUI-primary-but-generic: uncommon item/object/system branches still use the generic visible component for the emitted prompt (generic labelled yes/no, generic item row, generic menu row, generic direction/target, or generic free-text field). This includes rare #monster/#ride/#turn/#wipe branches and unusual tool-specific follow-ups. They are not raw-only for normal play, but their labels may lack deep state-specific semantics.
  • Advanced-only raw fallback: raw selector letters, object-class symbols, count/range syntax, command names, vi/numpad target keys, and any-key read-only dismissal remain supported for expert speed and NetHack compatibility. They are documented as optional fallback, not primary normal UI.
  • Blocked by missing structured NetHack data: authoritative coordinate protocol/line-of-effect/range, travel path interruption feedback, real encumbrance/debt simulation, exact inventory class availability, known/discovery class summaries, spell/skill/option data models, polymorph slot and offhand legality, true cursed/stuck status before prompts, prayer timeout, and terrain-specific sit/pray/offer consequences. Current UI shows visible controls/placeholders where possible and does not fake unavailable state.

Gaps / uncertainty

  • This is source/fixture/test inspection, not an exhaustive live playthrough of every possible NetHack branch. NetHack can emit arbitrary yn_function, getlin, select_menu, get_ext_cmd, and direction prompts from many item- and state-specific code paths.
  • Wizard/debug commands exist in src/cmd.c but are not normal current-player workflows unless wizard mode is active; they were not enumerated individually except as unavailable/internal catalog filtering evidence.
  • The Electron shim bridges only one-character safe playable keys and line/menu answers. Therefore any NetHack command reachable by typed key/# command can surface typed prompts even if no dedicated quick-action button exists.
