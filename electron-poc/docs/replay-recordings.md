# Recorded-session replay checkpoints

The Electron POC accepts both legacy `nethack-electron-input-recording/v1` files and `nethack-electron-input-recording/v2` files with authored screenshot checkpoints.

## v2 recording model

A v2 recording has:

- `schema: "nethack-electron-input-recording/v2"`
- the effective deterministic `seed` captured from the shim bridge for every run; when recording is enabled and the UI seed field is blank, the recorder generates and fills a bounded deterministic seed before NetHack starts so the recorded run can be replayed exactly
- `playerSpec`, `character`, `options.NETHACKOPTIONS`, `settings`, and `window` metadata captured for replay setup
- `events[]` containing replayable `{ type: "input", key, keycode, source }` entries, authored `{ type: "checkpoint", name }` entries, and preserved non-replay evidence records for protocol review
- `inputs[]` retained as a legacy compatibility projection of input events only

The New Game modal's **Record inputs for replay** checkbox starts a v2 recording. While recording, the normal game view shows a visible **Recording replay** toolbar with **Add screenshot checkpoint** and **Save recording** controls, so checkpointing is discoverable during play. The debug panel keeps mirror controls for diagnostics. Each checkpoint records the current renderer automation state as review metadata. Saving uses the existing `test/recordings/*.nhrec.json` path.

All gameplay-affecting Electron UI paths use the same recorded keycode shim-input wrapper. Automatic key answers generated by the UI, such as game-over disclosure prompts and game-over menu spacing, are recorded with `source` values like `auto-disclosure` or `auto-menu-space` so replay sees the same input stream. Unsupported non-keycode shim payloads are not part of the recorder's supported input model; if one is attempted while recording it is blocked/flagged and recording save fails instead of silently creating an un-replayable hidden input.

## Replay behavior

Both replay paths use `src/shared/replay-adapter.js`:

- `scripts/replay-recording.js` replays v1 `inputs[]` or v2 `events[]` input entries through the shim bridge.
- `scripts/replay-visual.js` / `src/main/replay-runner.js` starts Electron with recorded seed/playerSpec/options/settings/window metadata, waits for renderer/shim state stability before sending inputs and before checkpoint captures, captures `start`, cadence, authored checkpoint, and `final` screenshots, writes per-checkpoint `*.state.json` sidecars, and writes `visual-replay-summary.json`.

Renderer-only UI state is not forced into the live game during replay; it is saved in checkpoint sidecars for review. Gameplay determinism comes from the captured seed, options/settings, player spec, and complete recorded keycode input stream. The startup intro overlay is dismissed during visual replay so screenshots show the replayed game surface rather than duplicate presentation chrome.

## Preserved v2 protocol evidence

Slice 1 of the UI architecture roadmap extends the v2 recording schema so recordings can preserve protocol evidence without changing replay behavior:

- `{ "type": "shim-event", "event": { ... } }` preserves v1 raw/normalized shim events.
- `{ "type": "ui-protocol-event", "event": { ... } }` preserves a validated `nethack-electron-ui/v2` event envelope.
- `{ "type": "ui-protocol-command", "command": { ... } }` preserves a validated v2 command envelope.
- `{ "type": "ui-protocol-ack", "event": { ... } }` preserves a validated v2 command/transaction acknowledgement event.
- `{ "type": "screenshot", "name": "...", "path": "..." }` and `{ "type": "state-sidecar", "name": "...", "path": "..." }` preserve artifact references.

Malformed embedded v2 events/commands fail recording validation closed. Command acknowledgement events (`command.accepted`, `command.rejected`, `command.completed`, and transaction acks) are preserved in the same non-input evidence stream; rejections include public blocker tokens such as `blocked.input.staleRevision` or `blocked.input.promptActive`. Replay still ignores these non-input records for gameplay and reports them as preserved evidence warnings rather than attempting domain behavior.

## End-to-end validation

`npm run test:real-record-replay-e2e` launches the real Electron app, records a real session from a blank seed field (the recorder fills a deterministic seed), sends an actual keyboard input, adds a named checkpoint through the visible toolbar, saves through the visible toolbar, replays that exact file visually, and asserts that checkpoint screenshots, sidecars, `visual-replay-summary.json`, and checkpoint state validation all pass.
